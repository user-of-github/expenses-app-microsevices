# AGENTS.md — receipt-service

Core REST API microservice for expense and receipt (cheque) management.

## Purpose

Provides endpoints for:
- **Classificators**: categories, payment methods, retail chains, shops
- **Cheques**: CRUD operations on receipts with line items

## Tech stack

- **C++23**, GCC 14
- **Drogon** HTTP framework (async coroutines)
- **Drogon ORM** (auto-generated models from PostgreSQL schema)
- **Jsoncpp** for JSON serialization
- **CMake** build system
- **PostgreSQL 17** (via `libpq`)

## Endpoints

### Health
- `GET /health` — liveness/readiness probe (Kubernetes), returns `{ "status": "ok" }`

### Classificators
- `GET /payment-methods` — list active payment methods
- `GET /categories` — list expense categories
- `GET /retail-chains` — list retail chains
- `GET /shops?retail_chain_id={id}` — list shops (optionally filtered by chain)
- `GET /shops/{id}` — get shop by ID

### Cheques
- `GET /cheques` — paginated list of receipts
- `GET /cheques/{id}` — get receipt with items
- `POST /cheques` — create receipt (body: `CreateChequeDto`)
- `DELETE /cheques/{id}` — delete receipt and items

## Code style & conventions

### Naming (enforced by `.clang-tidy`)

| Element | Style | Example |
|---------|-------|---------|
| Namespaces | `snake_case` | `expenses::cheques` |
| Classes / structs | `CamelCase` | `ChequeController`, `CreateChequeDto` |
| Functions | `snake_case` | `get_all`, `parse_item` |
| Variables | `snake_case` | `repository_`, `total_amount` |
| Class members | `snake_case` + `_` suffix | `repository_`, `status_code_` |
| Constants | `CamelCase` + `k` prefix | `kDbClientName`, `kMaxRetries` |
| Enum values | `CamelCase` + `k` prefix | `kPending`, `kCompleted` |
| Files | `snake_case.{hpp,cpp}` | `cheque_controller.hpp` |
| Include guards | `#ifndef SERVICE_PATH_FILE_HPP` | `#ifndef RECEIPT_SERVICE_CHEQUE_CONTROLLER_HPP` |

### Architecture patterns

1. **Controllers** derive from `drogon::HttpController<T>`:
   - Register routes in `METHOD_LIST_BEGIN` / `ADD_METHOD_TO` / `METHOD_LIST_END`
   - Handlers are `drogon::Task<drogon::HttpResponsePtr>` coroutines
   - Inject repositories as private members

2. **Repositories** encapsulate DB access:
   - Use `drogon::orm::CoroMapper` for async queries
   - Obtain client via `get_db_client()`
   - Return domain types or aggregates (e.g., `ChequeAggregate`)

3. **DTOs** handle request/response shapes:
   - `static parse(const Json::Value&)` — deserializes + validates
   - Throws `BadRequestException` on invalid input
   - Keep validation logic in DTO, not controller

4. **Responses**:
   - Use `expenses::common::to_json_response(...)` for Drogon models (anything with `toJson()`)
   - For aggregates, build `Json::Value` manually in controller

5. **Errors**:
   - Throw typed exceptions: `BadRequestException`, `NotFoundException`, etc.
   - Global handler in `main.cpp` converts them to JSON `{ statusCode, message, error }`
   - Do not build error responses by hand

### Environment variables

Read at startup via `std::getenv` (see `src/common/env.hpp`):

| Var | Purpose |
|-----|---------|
| `POSTGRES_DB` | Database name (must match `expense_db` for generated ORM namespace) |
| `POSTGRES_USER` | DB user |
| `POSTGRES_PASSWORD` | DB password |
| `POSTGRES_HOST` | DB host (`127.0.0.1` locally, `postgres` in Docker) |
| `POSTGRES_PORT` | DB port (default `5432`) |
| `CHEQUES_SERVICE_APP_PORT` | Service port (default `4000`) |

When running from CLion, the **Run Configuration environment string must match `.env`**.

## Build & run

### Docker (recommended)
```bash
cd ..
docker compose --env-file .env up --build receipt-service
```

### Locally
```bash
# Prerequisites: Drogon, Jsoncpp, libpq, openssl, uuid, zlib dev packages installed system-wide
cmake -S . -B cmake-build-debug
cmake --build cmake-build-debug
export $(grep -v '^#' ../.env | xargs)
./cmake-build-debug/receipt_service
```

### Regenerate ORM models
```bash
# DB must be running with migrations applied
sh ./generate-drogon-orm-models.bash
```

## Critical rules

1. **Add new `.cpp/.hpp` files to `CMakeLists.txt` `add_executable(...)` list.** Only `src/db/*.{h,cc}` are auto-globbed.
2. **Never hand-edit `src/db/__generated__/`** — files are regenerated by `drogon_ctl`.
3. **Keep DB name consistent** with generated ORM namespace (`drogon_model::expense_db`).
4. **clang-tidy runs with `WarningsAsErrors: "*"`.** Fix all warnings before committing.
5. **Do not commit `cmake-build-debug/`** or `.env`.
